## 工作台四步页面骨架统一（盒子样式一致）

用户反馈「声线创建步骤 1/2/3/4 页面设计不一致，要求盒子样式统一保持大盒子」。实测后确认根因不在组件写法，而在一条遗留 CSS。

### 根因（已修）

`globals.css` 的 `.content-wrap { margin: 0 auto }` 是旧 block 布局遗留。`.main-panel` 改成
`display:flex; flex-direction:column` 后，flex 子项带交叉轴 auto margin 会让 `align-items:stretch`
失效，宽度塌成 fit-content —— 四步实测宽度曾是 **762 / 1229 / 755 / 1229**，左边界 531/297/534/297，
切步骤时整块内容左右横跳。修法：`theme.css .content-wrap` 加 `width:100%`（max-width:1580 仍生效）。
修完四步统一 1229 @297（1600 视口）。**这条要注意：其他页面（全部声线/系统状态等）也随之变宽，
属于同一个 bug 修复，不是新问题。**

### 新增骨架（theme.css）

- `.step-stack`：页面顶层纵向堆叠，`gap:18px`，区块间距唯一来源；`.step-stack > *` 强制 `margin-top:0`。
- `.panel-flush`：列表型大盒子，`padding:0` + `.panel-heading`(16px 18px) 承担留白，表格/行贴边。
  **`.products-panel` 作为旧名与它共用同一组规则**，不要各写一套。
- `.panel-inset`：flush 盒内非列表内容的留白（14px 18px），首末元素 margin 归零。
- `.step-footer`：底部「下一步」操作条，同款大盒子。
- `.summary-strip`：步骤4 顶部三段统计（替代原来的 `.output-summary` 三张独立小卡）。

### 坑（踩过）

- **步骤3 的类名不能从 `.products-panel` 换成 `.panel-flush`**：`.products-panel .result-edit-row select{width:118px}`
  （theme 584 + globals）是挂在旧类名后代上的，换了之后下拉吃掉整行，台词框被挤成竖排一条。已回退保留 `panel products-panel`。
- `.panel-heading` 改 flex 后 `float:right` 失效，计数胶囊要靠 `> span{margin-left:auto}` 顶到最右；
  有 `em.heading-hint` 时则 em 吃 auto、span 退 8px。
- 候选区进 flush 盒后，`.candidate-rail` 的左右内边距从 22px 降到 18px（容器已自带 1px 边框 + 18px 内边距，

## 下午：第 1 步"操作失效"根因修复 + 从声线库挂声线

### 根因：写操作不清 GET 缓存

`lib/api.ts` 的 `apiGet` 有 5 秒 `GET_CACHE`，但 `apiSend` / `apiUpload` 成功后只发
`noteProjectWrite`（通知侧栏排序），**从不失效缓存**。于是所有"写 → 立刻重新拉取"的链路
都命中旧快照：后端 200、界面纹丝不动、也没有 toast。

实测（红楼梦·林黛玉）：点「暂存」→ POST shortlist 成功 → 按钮仍显示"暂存"、暂存区不出现、
无提示；等 5 秒也不会自己变（React state 还是旧的，不会重新请求）。选定、移除、删除槽位、
改名、keep-all 全中同一枪。这就是用户说的"移除/暂存等操作无法正常操作"。

修法：`noteProjectWrite` 第一行 `GET_CACHE.clear()`（写后整体失效，条目只有几十个，
比按路径前缀匹配可靠），`apiUpload` 也补上调用。

### 顺带修掉的静默失败

- `select` / `toggleShortlist` / `keepSingle` 的 `if (!activeRequestId) return` → 改成
  `notify('请先在左侧选择一个声线槽位')`；暂存/移出成功各补一条 toast（原来只有卡片角标变化）。
- 暂存区改成**常驻**（原来是 `shortlisted.length > 0 &&` 条件渲染）：空时显示
  `.shortlist-empty` 一行说明，用户才知道有这块功能。
- `useVoiceRequests.createSlots` 原来 `setRequests(result.items)` —— `items` 是数据库原始行，
  没有 `tag_list`/`tag_ids`，覆盖后**已有槽位的标签列会当场变空**。改走 `loadRequests()`。
- `RequestTable` 改名：Enter 提交后 input 卸载再触发一次 blur → 重复 PUT；Esc 取消后 blur
  反而把改名提交上去。用 `editingRef` 门控（`finishEdit` 先判 ref、`cancelEdit` 清 ref）。
  实测：Enter 只发 1 次 PUT；Esc 后 0 次 PUT。
- 「全部声线」页「加入项目」原来唯一反馈是 2.6 秒就消失的 toast → 已在本项目清单的声线
  按钮直接变「已加入」并禁用（`rosterIds` 判据）。

## 成品页「换用历史版本」（用户问「新生成的不如原来的怎么办」）

排查确认这是功能缺口，不是操作不会：第 4 步只读 `outputs.output_mp3` 当前值，第 3 步的
「历史版本」只有 `<AudioPlayer>`、没有任何写入口，`output_versions` 表纯只读留档。

### 落地（方案 A，用户选定）

- `studio/batch.py` 新增 `use_version()`：取 `output_versions` 那一版 → **复制**成
  `{pos:04d}_{voice}_v{new}.mp3` → 更新 `outputs`(output_mp3/version/text/in_final=1) →
  `demote_siblings` → `_record_version` → manifest + activity("换用历史版本")。
- `studio/api.py` 新增 `POST /api/projects/{pid}/batch/{item_id}/use-version`（body `{version}`），
  `/outputs` 给 batch 行挂 `versions`（复用 `batch.version_histories()`）。
- 前端：`ProductsPage` 成品行加 `.output-versions` 折叠 + 「换用这一版」；
  `ResultRow` 历史版本行同款按钮，两处共用一个接口。样式进 `theme.css`（不碰 globals.css）。
- `VERSIONS_KEPT` 3 → 5（用户选的），重录 5 次内仍能回退。

### 为什么是"复制成新版"而不是改指针（重要）

1. `_next_version` = `version+1`。把 `outputs.version` 改小，下次重录的新版本号会撞上已有
   `(output_id, version)`，`INSERT OR REPLACE` 当场覆盖那版记录。
2. `_prune_versions` 按版本倒序删文件。两版共用同一路径时，剪掉一条会连另一条的音频一起删。

代价：`outputs.version`（重录次数）会虚高一格，界面显示"第 N 次录音"但内容是旧版。
要彻底干净得给 outputs 加 `current_version` 字段（需迁移），本次没做。

### 验证

数据目录副本 + `fastapi.testclient`：`/outputs` 带 versions ✓；调接口后音频字节 == v1、
version 2→3、text 回退成旧版台词、in_final=1、v1/v2 旧文件都还在、版本记录 1/2/3 完整 ✓；
请求不存在的版本返回 400「该历史版本已被清理，无法换回」✓。tsc --noEmit 通过。临时脚本与副本已删。

## 上传声线「试听」按钮 422（字段名不统一）

用户报"调用上传声线克隆时返回 422"。**422 在 FastAPI 里只有一个来源：请求体校验失败**
（`as_http_error` 统一返 400，业务异常不会出 422），所以不用怀疑模型或数据库。

根因：`UploadVoicePage.buildForm()` 一份表单喂两个接口 ——
`/api/voices/upload` 的朗读文本字段叫 `preview_text`，`/api/tools/clone` 历史字段叫 `text`
且是 `Form(...)` 必填。合并工具页（2026-10-20 删独立工具页）时表单统一成 `preview_text`，
clone 那边没跟着改，于是**「入库」能成功、「试听」必 422**，
detail 是 `[{"loc":["body","text"],"msg":"Field required"}]`。

修法：`tool_clone` 的 `text` 改 `Form("")` 并新增 `preview_text: str = Form("")`，
取 `text.strip() or preview_text.strip()`。两边都收 → 旧前端/脚本调用也不炸。
`UploadVoicePage.buildForm` 补注释写明这个字段名差异，别只发一边。

验证：原样入参（只有 preview_text、无 text）不再 422，走到业务层被 ffmpeg 判假 wav(400)；
两字段皆空时返回 400「请填写需要生成的文本」（不是 422）。tsc 通过。
