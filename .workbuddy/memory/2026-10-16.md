## 前端页面切换架构决策
- 症状：侧栏切页，第二次点击同一页面会重新加载（转圈/重发请求）。根因 `app/page.tsx` 用条件渲染（if/return），切页即卸载+重挂载；各页面 useEffect 拉数据，且 `lib/api.ts` 的 GET 带 `cache:'no-store'`。
- 推荐方案（尚未实施，等用户确认）：A) 常驻挂载 + `hidden` 显隐实现 keep-alive；B) `lib/cache.ts` 的 `useApiResource` 做 stale-while-revalidate 兜底。需配套：隐藏页暂停 `usePolling`、隐藏页暂停 AudioPlayer。
- 结论：不需加路由系统来治这个病。Next App Router 子页面导航时仍重挂载，RSC 缓存不适用于全 `'use client'` 架构；路由仅带来深链/后退/代码分割，属独立决策。若以后上路由，须把 useProjects/useToast/步骤状态抽进 Context Provider，且 A/B 仍要保留。
- 二次确认（11:10）：本 SPA **没有必要加路由**。它是单机单用户 localhost 工具（后端 7871），深链/分享/SSR/代码分割价值都低；唯一的真痛点 F5 刷新丢失位置，用 sessionStorage 记 page+projectId+step 即可解决，无需重构上路由。路由仅当"需多人分享链接 / 公网多租户 / SSR"时才值得。

## 已实现：方案 A+B（11:20）
- 方案A（page.tsx）：用 `visitedRef`(Set<Page>) 记录首次访问，所有页面改为常驻挂载 + `hidden` 显隐（`.page-slot[hidden]{display:none!important}` 加在 app/globals.css）。切页不再卸载重挂载，第二次点回同一页秒开、状态/数据保留。Sidebar 的 onNavigate 改为 `go()`（先标记 visited 再 setPage）。
- 方案B（lib/api.ts）：新增 GET 结果内存缓存（TTL 默认 5000ms，stale-while-revalidate）。重挂载时命中新鲜缓存秒返回；实时轮询统一带 `force:true` 绕过缓存。
- active 透传：WorkflowPage 收 `active` 向下传给 VoiceWorkbench/BatchPage/ResultsPage/ProductsPage；useVoiceGeneration、useBatch、ProductsPage、VoiceRegenPanel 的 usePolling 用 `enabled={active}` 暂停隐藏页轮询（force 保实时）。
- AudioPlayer 加 IntersectionObserver，页面被 keep-alive 切走（display:none）或滑出视口时自动暂停播放。
- `next build` 通过（仅 pre-existing 的 autoprefixer/flex-end 警告）。注意：本机 sandbox 的 bulk-delete guard 会拦 next 清 .next 缓存，需在 sandbox 关闭下构建。

## 「上传声线」相关模块盘点 + 页面改版设计（未改代码，仅出设计）

用户要求：重新设计「上传声线」页，需含①正常上传克隆 ②音频"语种转化"；先盘点现有模块，只出设计不改代码。

**现有 5 个相关模块（实测代码确认）**：
1. `features/assets/UploadVoicePage.tsx`（侧栏 声线库→上传声线）— **唯一存档入口**。上传参考音频→
   克隆试听→固化入全局声线库（写 voices 表 + prompt.safetensors），可选同时关联某项目清单。
   后端 `POST /api/voices/upload` → `service.archive_uploaded_voice`。有全局按参考音频 MD5 去重。

   `TEMP_DIR/standalone/voiceclone/`。后端 `POST /api/tools/clone`。
3. `features/tools/ConvertTool.tsx`（侧栏 工具→音频转换）— **纯格式转换**（WAV 24kHz↔MP3 128kbps），

   **与语种无关**，全仓无任何语音翻译/语音转换(VC/STS)实现。
4. `features/batch/AddLibraryVoice.tsx` — 从全局库挑现成声线**关联**进项目（只写 project_voices，不上传）。

**关键技术事实（决定"语种转化"能不能做）**：
- 模型栈只有 Qwen3-TTS 的 `voice_design` + base `clone`，都是 **TTS（文本→音频）**，**没有** STS/VC 模型。
  所以"把一段中文音频直接变成英文音频（保留音色）"做不到（除非 ASR→翻译→TTS 三段拼）。
- **能做的**是「跨语种克隆」：`model_manager.create_prompt(ref_audio, ref_text, x_vector_only)` 产出的
  prompt **与语种无关**（只有 speaker embedding + ref_code）；生成时 language 是**独立入参**
  （`voices.generate_with_voice(voice_id, text, language, ...)`）。
  即：任意声线可读任意语种，`voices.language` 只是元数据、**不锁语种**。
- 注意 `voices.language` 的真实语义被误导：`archive_uploaded_voice` 里 `language` 只用于
  **试听文本**（`clone(preview_text, language, ...)`），**不参与** create_prompt，也不约束日后生成。
  所以 UI 上把 language 放在"参考音频"旁边的位置是**错的**，它属于"试听文本"。
