## 项目总览「···」行内菜单：从 absolute 改 fixed 浮层

- 症状：点 `···` 后菜单不是浮在页面上层，而是被表格"吃掉"——表格外层 `.table-wrap{overflow:auto}`
  把绝对定位的弹层裁掉，同时浮层的溢出计入滚动区，整块表格跟着变形（用户描述"挤压盒子原有的大小"）。
- 修法：新建 `components/ui/RowMenu.tsx`（触发器 + 弹层同组件），弹层 `position:fixed`，
  打开瞬间量触发器视口坐标。与 `.xselect-panel` / `.audio-volume-pop` 同一套手法（globals 第 30 行已注明）。
- **坑一：右对齐不能用 `right`。** `fixed` 的包含块宽度比 `documentElement.clientWidth` 少一条
  纵向滚动条（实测 1484 → 1469），`right = clientWidth - rect.right` 恒偏 15px。
  改用 `left: rect.right` + CSS `transform: translateX(-100%)`，按自身宽度左移，与包含块无关。
  代价：入场动画必须自带 `translate(-100%, …)`，不能复用 `xselect-pop`（它是 translateY）。
- **坑二：`window.innerWidth` 也算进了滚动条**，垂直空间要用 `documentElement.clientHeight`。
- 翻转：下方放不下且上方更宽裕时向上翻（估算高度 = 项数×31 + 10，与 `.row-menu button` 行高对应）。
- 已删除 `menuId` state；菜单项改为按项目状态裁（已删除项目只剩「彻底删除」），
  点项即关菜单再开弹窗。实测：右边缘偏差 0、下方间距 4px、表格 scrollWidth 前后都是 1107 无变化、
  底部行自动上翻（menu.bottom 726 ≤ trigger.top 736）、外部 pointerdown / Esc / 滚动均关闭、
  重命名与删除两条链路弹窗正常。

## 成品导出：语速控制（导出时变速，源文件不动）

需求原话："类似播放倍速……在成品导出的地方添加一个语速导出控制选项，导出的是母本改变后的副本，不是原文件"。
方案文档：`design/speed-control-design.md`（含实测数据与验收结果）。

- **语速不是模型参数**。`ModelManager` 只有 `design()`（instruct 里能写"语速稍快"）
  和 `clone()`（韵律继承参考音频，文字指令无效），两者参数表都没有 speed。
  批量台词走 clone，所以只能在导出层做 ffmpeg `atempo`（WSOLA，保基频）。
- 落点：给 `/api/files/{path}` 加可选 `speed`（ge=0.5 le=2.0），speed=1.0 仍走
  `_audio_response` 的 FileResponse，**URL 与改造前逐字节一致**。路径安全校验一行没重写。
- `speed != 1` 时改成 `tempo_stream` 流式现算（`-f mp3 pipe:1`），不落临时文件；
  实测单条 5 秒音频 66ms / 65KB。生成器 `finally` 里 kill 子进程 —— 关页面不能留僵尸 ffmpeg。
- 三条导出通道全接：`export-plan` 把 `speed` 编进每条 url（鉴权时有 `?token=`，
  追加要用 `&`）；`archive.zip` 逐条变速进 `TemporaryDirectory`、压实一条就删；
  `export_completed_batch` 直接 `tempo_to_file` 落盘。
- **头号风险**：`run_ffmpeg` 带 `-y`，导出目录若等于成品目录，变速会覆盖母本。
  `export_completed_batch` 在写任何文件前整体遍历拦截；`tempo_to_file` 自己也有
  `source.resolve() == destination.resolve()` 断言。
- manifest 加 `"speed"` 字段，**两处手抄的表必须同步**：`exports._build_manifest`
  与 `frontend/lib/localExport.ts` 的 `written.map`。
- 前端：`ProductsPage` 导出面板加 `.speed-options` 分段胶囊（0.9/1.0/1.15/1.25/1.4/1.5），
  localStorage 记忆（首帧固定 1.0 再在 effect 里读，否则 SSR/hydration 不一致）。
- **试听即预览**：`AudioPlayer` 加 `rate` prop 写 `playbackRate` + 显式 `preservesPitch`，
  成品列表点播放听到的就是该倍率 —— 先听再决定，避免"导完才发现太赶"。
- 实测（蜡笔小新 15 条）：1.0x 副本 md5 集合与源完全一致；1.25x 逐条比值 1.239~1.250；
  源文件全程 md5 未变；越界倍率 422。
- **倍率不会精确等于设定值**：mp3 帧对齐 + 编码器延迟是常数项，5~8 秒台词几乎无感，
  0.7 秒短句在 1.4x 下实测比值 1.396。不影响听感，只影响毫秒级对齐。

## 语速 v2：改成逐条倍率（当天下午迭代）

用户反馈两条：①只有部分台词要加速，不是全部；②每条台词旁边要一个自己的倍速按钮，默认 1.0×、可调。
方案文档加第 11 节。

- **倍率键用 `order_key`（`batch:<id>` / `single:<id>` / `supplement:<id>`），不是序号**。
  序号随拖动排序变，倍率会错位到下一条台词上；order_key 绑的是那条成品本身。
- 查询串格式 `speeds=batch:xxx|1.25,single:yyy|1.4`，分隔符 `|` —— **order_key 自己带冒号**，
  用 `:` 分隔会 rpartition 到错的位置。`_parse_speeds()` 解析不动的片段跳过（按原速），
  链接被手工改坏时整批失败更糟。
- `_build_manifest` 的 `speed` 参数降级为"整批兜底"，新增 `speeds` 按 order_key 覆盖；
  **整批先过 check_speed**，非法值在碰磁盘前 400。
- `iter_archive` 不再用单一 speed：逐条读 `entry["speed"]`，任一条非 1.0 才进临时目录分支，
  原速条目仍 `bundle.write` 原文件（不重新编码）。
- **覆盖母本拦截条件必须改**：原来判断"整批倍率非 1"，混着来的时候会漏判，现在判断
  "清单里存在任一变速条目"（`retimed` 列表非空）。
- 前端：`.speed-chip`（原速灰胶囊 / 非原速 accent 高亮）+ `.row-speed-pop`
  （fixed 锚定，同 `.row-menu`；绝对定位会被 `.product-list` 裁掉）。弹层 300px 宽，
  **5 个快捷档才放得下一行**（6 个会折行）；高度估算 175 要略大于实际 155，
  向上翻转时才不会压住触发器。
- `.panel input` (0,1,1) 会给 range 滑条套输入框底色和描边，必须
  `.row-speed-pop input.row-speed-range` (0,2,1) 压回裸滑条。
- 导出面板的全局倍率换成「全部台词」批量档：全部同值才点亮，混着都不亮。
- 实测（真实服务）：`[1.25, 1.0, 1.4, ...]` 逐条生效，未设的行逐字节等于源文件；
  批量 15 条 → ZIP 参数 799 字符；还原后 localStorage 存 `{}`。

## 新建项目向导：分段控件选中色块没铺满（用户反馈）

- 症状（暗色）：`.wizard-dims` 的「按项目 / 按标签」选中块比外框矮一截，底部留一条深色空档，
  与左边的搜索框也不同高。
- 真因：`.wizard-dims button { height: 32px }` 写死。`.wizard-picker-bar` 是 flex 且默认
  `align-items: stretch`，输入框内容高 39.25px 把外框撑到 39.25，按钮固定 32px 就贴在顶部，
  **底部空 5px**。像素级取证：外框 y7..45（39px），蓝色块 y8..39（32px），y40..44 是 field-bg。
- 修法：按钮去掉 fixed height，`display:inline-flex; align-items:center; justify-content:center;
  min-height:30px; white-space:nowrap;` 让 flex 拉伸填满内容区；`.wizard-dims` 补
  `align-self:stretch`。实测 active 37.25px = 容器内容高 37.25，光/暗两套主题都对得上搜索框。
- **通用教训**：flex 行里与输入框并排的定高控件，高度不要写死数字 —— 输入框高度会随
  padding+字体+行高变（这里 39.25 而不是整数），写死必然差几像素。要么 stretch，要么共用变量。
- 验证：headless Chrome（`--headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/cdp-prof-xxx`，
  别用 `rm -rf` 删旧 profile —— 549 个文件会触发 safe-delete guard 直接毙掉整条命令）
  + Node 22 内置 WebSocket 跑 CDP；用 `getBoundingClientRect` 量 active/容器/输入框三者高度最直观。
  流程注意：名称输入框要先 `dispatchEvent(new Event('input'))` 才能解锁「下一步」。
