## 大模型应用视角评估报告（design/llm-application-review.md）

- 用户要求从「提示词工程 / RAG / 模型配置」角度分析本项目。新增 `design/llm-application-review.md`，
  全文只用代码实测结论并标行号。
- **定性结论**：这是「生成模型应用」而非 LLM 应用 —— 依赖只有 torch + qwen-tts，无任何 LLM SDK / embedding / 向量库。
  所以按三类比较：同构的（提示词工程、上下文缓存、输出守门）、天然不需要的（多轮编排、工具调用）、缺失但该补的（检索增强、prompt 版本化、推理可观测性）。
- **新查实的关键事实（本次首见，值得记住）**：
  1. **`voices.prompt` 只写不读** —— 两处 INSERT 写它，合成路径零处读取。固化后声线只吃 `prompt.safetensors` 的
     speaker embedding，自然语言描述退化为「人类可读溯源标签」，**改描述不会改声音，声线不可编辑**。
     这是项目最核心的架构特征，也是「提示词工程做得最认真、却用完即冻结」的矛盾点。
  2. **六段式词表与 11 个场景模板是两套真相源，漂移约 45%**（逐段比对 55 段：voice 7/11、tone 7/11、mood 6/11、
     timbre 4/11、pace 1/11 不在词表内）。例：模板「约25岁/23岁/28岁/33岁/38岁/42岁/8岁」词表都没有；
     「语调沉稳有分量」「语调节奏感强」「语气耐心亲切」词表都没有。修法：模板改为喂 `composePrompt()` 的 selection 对象。
  3. **design 路径 `max_new_tokens=512` 固定 = 40.96 秒硬顶，且 `design()` 无任何输出校验**（对比 clone 的 5 次重试 + 三重判定）。
     守门只保 clone，design 裸奔 —— 这是最该优先补的技术债。
  4. **可复现性三条路径三种结果**：候选生成可复现（seed 落 `candidates.seed` + `manual_seed`）；
     `tools.design_sample` 的 seed **用完即丢**不落任何地方；`clone()` **完全没有 `manual_seed` 调用**，
     所以批量重生成必然全变调（版本机制只是「留旧版」不是「同版重放」）。
  5. **`prompt.safetensors` 的 metadata 只有 ref_text / x_vector_only / icl_mode，不含模型标识** →
     `.env` 允许换 clone 模型（0.6B→1.7B），换后旧声线资产若维度相同则**静默变声**，无告警。
  6. **RAG 基础设施为零**：全仓 `embedding|retriev|faiss|vector` 零命中；声线库去重是 `audio_hash` **MD5 字节级精确匹配**
     （换编码/裁静音即失效）。合理，因为 TTS 的 instruct 是控制信号不是知识查询。
     三个真实落点：① 声线库语义检索（prompt+ref_text+tags 做 embedding，本地小模型 + SQLite 暴力扫即可）②
     优秀 prompt 的 few-shot 检索（需先做 prompt 版本化）③ 音频指纹近似去重。
     **明确不建议**引入向量库做文档问答（没有知识文档）。
  7. 同构亮点：`prompt.safetensors` = LLM 的 embedding/KV 缓存（把「每次重编码参考音频」前置到固化一次）；
     clone 的 `ref_audio + ref_text`（ICL）= few-shot 示例对，`x_vector_only=True` = 只给 system prompt 定人设不给示例。
- 评分：提示词工程 B+ / ICL A- / 提示词闭环 C / RAG D / 模型配置 B / 可复现性 C+ / 可观测性 C。
- 建议优先级 P0（design 守门 + 显式传采样参数 + clone 补 seed）→ P1（prompt 版本化 + `(prompt,seed,model)` 三元组入库）
  → P2（声线库语义检索）。
