# 订单详情 UI 设计方案（草稿）

## 设计目标

- 延续项目现有的浅色后台工作台：灰白画布、白色卡片、紫色强调色。
- 将订单信息拆成「订单概览 / 用户详情 / 用户票卷」三层，降低信息密度。
- 票卷状态在展示层完成字典映射，不直接显示数字编码。
- 成功状态统一使用绿色，异常状态统一使用红色，处理中使用暖黄色。
- 异常票卷的操作列保留后续锤子入口位置，本稿不展开具体操作面板和按钮行为。

## 建议的状态映射展示

| 原始编码 | 建议展示文案 | 样式 |
| --- | --- | --- |
| 100 | 成功 | 绿色圆点 + 浅绿色胶囊 |
| 200 | 失败 | 红色圆点 + 浅红色胶囊 |
| 300 | 处理中 | 暖黄色圆点 + 浅黄色胶囊 |
| 未知编码 | 未知状态 | 灰色提示，便于发现字典遗漏 |

编码仅作为辅助信息保留在「原始编码」列，用户主要阅读「展示状态」。

## 页面结构

1. 顶部面包屑、页面标题和返回/编辑操作。
2. 订单概览卡：订单编号、订单状态、金额、票卷进度。
3. 用户详情卡：用户昵称、用户 ID、联系电话、收货地址、备注。
4. 用户票卷表：票卷编号、票卷类型、原始编码、展示状态、更新时间、操作。
5. 异常行操作列：本稿使用虚线「锤子入口（预留）」占位，待下一轮确定具体动作。

## 评审重点

- 数字编码不再作为主信息出现。
- 失败状态在表格行内可被快速扫描，且不会破坏正常状态的视觉层级。
- 操作列保留足够宽度，后续加入锤子按钮时无需重新调整表格结构。
